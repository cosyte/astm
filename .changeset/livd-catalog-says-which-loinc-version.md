**A LIVD catalog can now say which publication it came from and which LOINC version the mapping was made against, and that version rides on every annotation.** A consumer could record the vendor rows and nothing about the publication behind them, so a mapping this library annotated was not reproducible (nothing said which version of LOINC it was made against) and the attribution statement the LOINC license requires had nowhere to live beside the mappings it applies to. Four optional publication-level elements now ride on the catalog itself, and the LOINC version rides onto every annotation the catalog produces.

Added:

- `LivdPublication`, supplied as an **optional second argument** to `defineLivdCatalog` and readable back as `LivdCatalog.publication`: `publisher`, `publicationVersion`, `loincVersion` and `loincCopyright`, every one of them optional. Each declared value is preserved **verbatim**, with no trimming, case folding, reordering, reformatting or defaulting. A value that is absent, empty or whitespace only is one case, no value declared, and is stored as absent rather than as a blank.
- `LivdAnnotation.catalogLoincVersion`: the catalog's declared LOINC version, carried on **every** annotation that catalog produced, whatever the lookup answered (`mapped`, `unmapped`, `ambiguous`, `no-vendor-code`, `no-code`). It is provenance about the CATALOG, and no field says any LOINC was checked against it, because none was.
- `ASTM_LIVD_CATALOG_NO_LOINC_VERSION` in `LIVD_WARNING_CODES`, with `AstmLivdCatalogWarning`, `LivdCatalogIdentity`, `LIVD_CATALOG_IDENTITY_UNDECLARED` and the builder `livdCatalogMissingLoincVersion`. A catalog defined with no LOINC version surfaces one such warning on `LivdCatalog.warnings`.

**It warns, and it never refuses.** A catalog with no LOINC version is built, indexed and answers every lookup exactly as it would have. The warning is raised **once, where the catalog is defined**, never per record, so the per-record stream `applyLivd` returns carries the same codes, in the same order, in the same number as before. No answer moves and no `mapped` becomes `ambiguous`.

**The warning's message is a constant and the catalog is named in a structured field.** The metadata is consumer-supplied text this library cannot vouch for, so interpolating it into a message would put whatever a consumer stored into every log that prints one. The message says nothing about the catalog; `AstmLivdCatalogWarning.catalog` carries the publisher and publication version the catalog declared. A catalog that declared neither is reported as having declared no identity (`LIVD_CATALOG_IDENTITY_UNDECLARED`), positively, and no name, ordinal or borrowed row value is invented to stand in for one.

**Nothing here is validated, and nothing here is a claim by this package.** There is no version format check, no copyright-text check and no publisher check. This package performs **no LOINC validation of any kind**, which is unchanged: it cannot tell a real LOINC version from a typed one and does not try, so `catalogLoincVersion` states what the consumer declared and never that a LOINC was checked, found or conformed against it. **Carrying an attribution statement is not discharging it**: the LOINC license obligation stays the consumer's, and this package supplies no statement on anyone's behalf.

**This is additive and source compatible.** The second argument is optional, so the existing single-argument call keeps working; `LivdCatalog.publication` and `LivdCatalog.warnings` are optional members, so a catalog a consumer implemented by hand still satisfies the interface and still annotates without raising; and `catalogLoincVersion` is conditional, so an annotation from a catalog declaring no LOINC version keeps the exact key set it has today. The one visible widening is `LivdWarningCode`, which gains the new registry member: an exhaustive `switch` over that union needs one more arm.
