Stop a delimiter set that names one of the escape mnemonics from altering the values it emits, and state what a header's delimiter-declaration surplus costs on emit.

The escape encoder ran as four chained whole-string substitutions: the escape character first, then the field, component and repeat delimiters. Going first protected the escape character it introduced, but nothing protected the `E`, `F`, `S` and `R` mnemonic letters it introduced, so a set naming one of those letters in another role re-escaped a mnemonic the encoder had just written. Emitting a leaf of `R` under a set whose field delimiter is `E` and whose escape character is `R` produced `RRFRR`, which reads back as `RER`.

Measured over the whole four-role space drawn from an 18-character alphabet, against a synthetic ten-record message: of the 50,400 delimiter sets the serializer accepted, 10,450 emitted a stream this library re-read with a different field tree, and 9,287 of those reported nothing outside the profile safety gate's tolerable allow-list, so a gate-legal profile plus `{ strict: true }` accepted the altered value. None of them was silent, but only because a non-canonical set always reports `ASTM_NONSTANDARD_DELIMITERS`, which is itself tolerable; silence was never available as a measure here and should not be read as reassurance.

The encoder is now a single left-to-right pass. Each character is read once and written either as itself or as a whole escape sequence, and nothing the encoder writes is examined again, which makes it the exact inverse of the decoder rather than approximately so. In that sweep no accepted set diverges. Bytes change for exactly the 10,450 sets that were diverging and for no others, so a canonical stream, and any set naming none of the four mnemonic letters, is byte-identical to before. Which records the serializer refuses is unchanged: that check reads the first character actually written, so it needed no adjustment when the encoder underneath it changed.

Paired with it, the one position where emit is deliberately not byte-exact is now stated wherever the preservation rule is. Only three characters of a header's delimiter declaration carry a role, and a declaration carrying more keeps the surplus. A surplus that could not be read back as one is dropped instead: that means a surplus carrying the field delimiter, or any control character, and it happens on the default canonical path as much as when transcoding, which the previous wording attached to transcoding alone. Probing one character at a time, 31 of the 33 C0 and `DEL` characters can reach a surplus and every one of them costs it; the remaining two are `CR` and `LF`, which end the record while it is being read, so no surplus ever holds them. The whole surplus is dropped rather than the offending character alone, because a subsequence of a run whose meaning is unresolved is a different run, not a shorter version of the same one. Nothing reports any of this, because emit returns a plain string. The behaviour is unchanged and long argued at its own site; what changed is that it is now measured, pinned, and stated on the surfaces that previously stated the preservation rule without its exception.
